# 通用输入条件五分类

「这个镜头用什么输入方式喂给模型」是所有视频生成模型共有的问题。业界各家
（MiniMax、Runway、可灵、即梦、Seedance 等）叫法不同，归纳为五类。
**判别思路在本文件；各模型的具体名称、模板、首行类型（结构化的标签与
秒值）、标签策略在其 profile 的 `conditions` 与 `tag_policy` 里；首行的
逐字英文句式以同目录官方模板为准。**

| 通用类 | 输入 | 适用 |
|---|---|---|
| **纯文本 T2V** | 只有文本，无关键帧 | 链首镜、内容可自由发挥的镜头 |
| **首帧引导 I2V** | 一张图作首帧，向后发展 | 需要严格承接上一镜画面 |
| **首尾帧 FI2V** | 首帧、末帧都给 | 开场和落幅都要锁定 |
| **尾帧反推 L2V** | 只给末帧 | 落幅确定、开场让模型补 |
| **全参考 Ref2V** | 多人/多物参考绑定，无关键帧锚点语义 | 群像、定妆式镜头 |

## 判别规则

1. **关键帧锚点是比「多参考」更强的语义**：一镜既需要首/末帧路径约束、
   又有多人绑定时，归 I2V/FI2V，人物通过参考标签引用，而不是 Ref2V。
2. **尾帧链的子镜统一归 I2V**：子镜拿父镜尾帧当首帧锚。具体在某个模型里
   写成什么模式名、用什么字段，看该模型 profile——H3 即 I2VA，不是 Ref2VA。
3. **一个节拍装不进单镜时长上限时拆镜**，拆出的新子镜同样走 I2V。
4. 模式在写词**之前**判定，写入该镜 gen.json 的 `mode`；判错则模板、字段、
   首行全部白写。

## 为什么必须显式判模式

模型内部会把多模态输入改写成结构化提示词（H3 的 Context-IR 即此类模块）。
输入怎么组织、参考怎么指派，直接决定结果；而模式决定了组织方式。所以宁可
在写词前花一分钟把模式判清楚，也不要写完一整篇才发现字段体系不适用。
