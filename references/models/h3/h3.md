## 1. H3 是什么
- 通用全模态生成系统：文本 / 图像 / 视频 / 音频在同一上下文统一理解与生成。
- 输出 **4–15 秒**；成片固定 **24 FPS**；音频 **32 kHz 立体声**。
- 支持宽高比：21:9、16:9、4:3、1:1、3:4、9:16；默认短边 768 像素。
- 分辨率档位 768P / 2K；2K 官方通过 H3-Regenerate 实现（见 §7）。
- 稳定支持 11 种台词语言：阿拉伯语、中文、英语、法语、德语、意大利语、
  日语、韩语、葡萄牙语、俄语、西班牙语；其他语言有不同程度支持。
- 一个内部模块（H3-Context-IR）会把多模态输入改写成结构化提示词，未开源
  ——所以**输入怎么组织、参考怎么指派**直接决定结果。

## 2. 调用契约（AutoDL ComfyUI 封装）
两步异步：
1. 提交：`POST https://autodl.art/api/v1/comfyui/comfyui_workflow/<workflow_id>`，
   返回 `task_id`
2. 轮询：`GET .../result/<task_id>`，
   status ∈ QUEUED / RUNNING / SUCCESS / FAILED / CANCEL
- 鉴权：header `Authorization: <raw token>`（令牌创建分组选 ComfyUI；不加 Bearer）
- 成功返回体 `code == "Success"`，`data.task_id`；results 元素是 dict：
  `{'type':'video','url':...,'file_type':'mp4'}`
- 结果 URL 有效期短，SUCCESS 后尽快下载
- 两个常见 workflow 的差异以服务端实际 options 为准：
  - 有的 workflow **ref_image_0 必填**
  - 有的 workflow **ref_audio_0 必填**，且分辨率选项不同
  - 它们分别对应官方 **FL2VA / Ref2VA** 两个 checkpoint 的封装（见 §3）
  - 提交前必须核对当前 workflow 的分辨率/必填项，不要凭记忆
- `ref_image_*` / `ref_audio_*` 需 URL；data URI（base64）AutoDL 实测可被
  接受，否则需托管（实测日期：2026-09，封装变更后需复核）
- **当前封装仅开放 768P**（2026-09-23 确认）；2K 选项何时开放以服务端为准。

## 3. 两个物理 checkpoint 与参考口径

H3 不是一个端点平等服务五种模式，而是**两个独立 checkpoint**（理解成两个
模型包）；「五模式」是提示词写法层，提交时还要投对包：

| checkpoint | 吃什么输入 | 服务的模式 | 投哪个 AutoDL workflow |
|---|---|---|---|
| **FL2VA** | 文本 + **0/1/2 张图**（无视频/音频参考） | T2VA / I2VA / FL2VA / L2VA | 图类 workflow（ref_image_0 必填那个） |
| **Ref2VA** | 文本 + 图/视频/音频多模态参考 | Ref2VA | 音类 workflow（ref_audio_0 必填那个） |

Ref2VA 的官方输入规格：

- **图像：** ≤ 9 张
- **视频：** ≤ 3 段；每段 2–15 秒；总时长 ≤ 15 秒
- **音频：** ≤ 3 段；每段 2–15 秒；总时长 ≤ 15 秒；**必须与图像或视频
  一起使用，不能作为唯一输入**
- **混合输入：** 所有类型文件总数 ≤ 12

> 两个直接的设计含义：
> 1. FL2VA 路径图片上限是 **2 张**——通常只能「Style Key + 首帧/末帧」。
>    需要多人/多物/场景/道具全部绑定时，该镜判 **Ref2VA**、投 Ref2VA
>    workflow。
> 2. 尾帧链子镜要首帧锚（I2VA，走 FL2VA 包），**带不了多人物定妆参考**：
>    角色一致性靠父尾帧画面本身 + Style Key，靠内容顺序长出，不能再塞图。

### 标签语义（以官方模板为准，勿自行窄化）

| 标签 | 含义 |
|---|---|
| `<Picture N>` | 作具体目标帧/关键帧/首末帧/构图锚点的参考图 |
| `<Subject N>` | **可复用的可见内容单元**：人物、动物、物件、场景/背景、服装、风格、动作、表情、姿势都可以；一个 Subject 可由多资产定义，一资产也可产出多个 Subject |
| `<Video N>` | 整段视频关系：剪辑源、续接起点、镜头运动/节奏/时间结构参考 |
| `<Audio N>` | 被复制或参考的音频：整曲复用、音乐风格、嗓音音色、台词、音效、节拍 |

标签一旦指派，在提示词所有段落保持同一含义。

### 槽位填充顺序（结构化口径：profile `tag_policy`）
在对应 checkpoint 的上限内按 [`profile.json`](profile.json) 的 `tag_policy`
填槽——顺序、编号、分组只以此处为唯一事实源，闸机强卡。要点：
1. **风格锚** Style Key：无父尾帧时占 `ref_image_0`；有父尾帧时父尾帧占
   `ref_image_0`、Style Key 紧随；
2. 然后 `<Picture N>`（帧/构图锚点，编号升序）、`<Subject N>`（其他可复用
   内容，编号升序）；**每张 member 整图占一槽**：定妆 sheet＝
   character-sheet、道具宫格＝prop-grid、场景宫格＝scene-grid（同时注明
   本镜 cell）；Ref2VA 最后是 `<Video N>`；
   - ★ **场景选格句（正文硬性）**：scene-grid 不能只给整张宫格，正文必须写
     `the <panel-position> panel of <Subject N> is fully referenced for this shot`
     （3×3 用 center/top-center/middle-left/… 同理），不点名第几格＝人审不通过，防模型混格。
     **single 单图无 panel**：写
     `the scene image <Subject N> is fully referenced for this shot`。
   - **cell → panel-position 映射（逐字照用，不自创译法）**：
     tl=top-left｜tc=top-center｜tr=top-right｜ml=middle-left｜c=center｜
     mr=middle-right｜bl=bottom-left｜bc=bottom-center｜br=bottom-right。
3. `<Audio N>` → `ref_audio_*`，编号独立；同文件多槽去重，保序。
- Style Key 的标签是 **`<Subject N>`**（官方 Subject 语义包含 Styles），
  父尾帧在 I2VA 里就是 **`<Picture 1>`**——gen.json 不写 `style-key` /
  `tail-frame` 这种自由标签。
- **gen.json 的标签一律带尖括号**；正文按官方模板：I2VA/L2VA/Ref2VA 带
  `<>`，唯 **FL2VA 官方句式（首行与正文）裸写 `Picture N`**——闸机两种都
  认，写词时照官方模板即可。
- 每张参考的职责写入 gen.json 的 `role`（受控枚举）；weak_reference 的
  retention 写法只在正文与人审环节，须写清只借什么、不借什么。
- **FL2VA 双帧占满 2 图槽时垫不下 Style Key**：闸机对该情形豁免，风格由
  正文风格句承担（人审确认）。

## 4. ★ 五模式判别与提示词结构

写词第一步不是动笔，而是判模式。**模式判错，后面全部白写。**

| 模式 | 触发条件 | checkpoint / workflow | 首行指令 | 模板 |
|---|---|---|---|---|
| **T2VA** | 无关键帧（链首镜通常如此） | FL2VA / 图 workflow | 无，直接三字段 | [base-en.txt](base-en.txt) |
| **I2VA** | 以参考图作**首帧**向后发展 | FL2VA / 图 workflow | `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` | 同上 |
| **FL2VA** | 首帧、末帧都给 | FL2VA / 图 workflow | `How the reference pictures align ... Picture 1 aligns with the 0.00-second mark; Picture 2 aligns with the S.SS-second mark ...` | 同上 |
| **L2VA** | 只给末帧，反推开场 | FL2VA / 图 workflow | `... <Picture 1> ... aligns with the S.SS-second mark ...` | 同上 |
| **Ref2VA** | 多人/多物全参考绑定（无关键帧锚点语义） | Ref2VA / 音 workflow | 无，六段依次 | [ref2va-en.txt](ref2va-en.txt) |

关键判别规则：

- **本流水线的尾帧链子镜 = I2VA，不是 Ref2VA。** 子镜拿父尾帧当首帧锚，
  主体字段写 `integrated_multimodal_description`，首行用 I2VA 逐字句。
  早期版本一律套六段式是错的。
- 同镜既需要首末帧路径约束、又有多人绑定时：关键帧锚点是更强的语义，按
  FL2VA/I2VA 处理，人物通过 Subject/Picture 标签引用；若绑定内容多到
  2 张图装不下，需要在拆镜（把绑定需求移到别的 Ref2VA 镜）与改写方案间
  取舍，不能超限硬塞。
- **FL2VA 优先设计成单镜头**：两帧间的连续插值是模型自己补的，单镜头
  最稳；多镜头仅当用户明确要求。I2VA/L2VA 同理，一条连续路径优先。
- 时间格式：对齐句中的秒数保留**两位小数**（`6.00`）；首行指令后空一行
  再写核心字段。
- 五种模式共同遵守的写法（剪切规则、运镜词表、说话人 ID、`<d>` 标签、
  scenetrans/cutoff、画面文字、声场两段）全部以收录的官方模板为准。
  脚本**不解析提示词正文**——这些写法在 G07 闸由人逐项对照模板人审，
  机器只卡 gen.json 结构、枚举与参考槽文件。

核心字段固定为：

- 基础四模式：`integrated_multimodal_description` → `overall_soundscape`
  → `non_diegetic_music`
- Ref2VA：`subject_definitions` → `summary` → `retention_analysis`
  → `detailed_description` → `overall_soundscape` → `non_diegetic_music`

**段名/段序与首行类型只登记在 [profile.json](profile.json) 的
`conditions[mode]`**（`core_fields`、`first_line`），gen.json **不再重复
手写** core_fields / first_line_instruction（出现即为废弃字段）；gen.json
契约见 [../../../schemas/gen-params.schema.json](../../../schemas/gen-params.schema.json)。
本模型的机器可查规格（checkpoint、槽位上限、分辨率、帧率、画幅、模板
映射、标签策略 tag_policy）统一登记在 profile；逐字英文句式不入 profile，
以官方模板为准，G07 由闸机提取结构 token、人审核对措辞。

**篇幅的官方口径**：只有 Ref2VA **生成类任务**的 `detailed_description`
有参考篇幅——normally 350–500 English words；对白密集以装下完整对白
时间轴为准，视频剪辑类随源片复杂度伸缩。基础四模式官方没有词数规定，
以细节覆盖 timeline 为准，不要反向套用数字。

## 5. 音频的正确口径（重点，曾反复改错）
- **一个角色一个 TTS wav**：用该角色的音色样本克隆嗓音，烧一段作声音
  参考；**台词内容不限**。
- 该角色**所有开口镜共用这一个 wav** 喂给 H3，不是一镜一个。
- **本镜实际要说的台词写在提示词里**（`<d>` 标签），不是靠 wav 内容。
- 音色样本（原始嗓音）只在克隆工序内部使用，**不另喂** H3。
- 锁镜/齐套只核 tts wav **路径存在且已审**，**不读取、不比对 wav 时长与
  镜头时长**——H3 凭声音参考自由生成。
- **时长约束两口径分清**：AutoDL 封装实测不卡参考 wav 时长；官方开放
  平台/本地部署口径为每段参考音频 2–15 秒、总时长 ≤15 秒。换直接调用
  官方接口时按后者执行。

## 6. 尾帧链
- 设计时在镜头卡写 `tail.tail_of` 与 `target_path`；路径预制。
- 成片后用 ffmpeg 抽裁切后成片的最后一帧（如 `-sseof -0.1 -frames:v 1`）。
- 子镜提交前若父尾帧缺失，脚本必须拒绝提交。
- 内容只能顺序长出，不可提前用静帧预制。
- 子镜走 I2VA（FL2VA 包），图槽上限 2：父尾帧 + Style Key 占满，角色
  造型/身份信息必须已经在父尾帧画面内，靠提示词约束延续，别计划额外
  定妆图。

## 7. 2K 与 H3-Regenerate
- H3 原生支持 768P / 2K。官方 2K **不是传统超分，也不是一个分辨率开关**：
  先由 H3-Base 出 768P，再把 **768P 成片 + 原始完整上下文（Context-IR
  扩展后的长提示词）** 一起回送 H3 重新生成 2K。
- 这样它看着自己的成片重画，招牌小字、精细纹理能补出来（超分模块只能
  猜测）。
- 官方 regeneration 请求体只有 model / content / resolution（无 duration、
  ratio）；I2VA 再生还要带原始首帧图。Ref2VA 的 2K 不走再生，直接带
  `resolution:"2K"` 生成。
- **当前 AutoDL 封装仅开放 768P，上述 2K 流程暂不可用。** 解封后：
  profile 的 `deployment.resolutions` / 顶层 `resolutions` 追加 "2K"，
  闸机自动按新枚举放行；本节描述再按封装实际形态修订。

## 8. 已知的坑（真实翻车记录）
| 坑 | 后果 | 规避 |
|---|---|---|
| 模式判错（尾帧链套 Ref2VA 六段） | 字段名/首行全错，首帧锚不生效 | 先按 §4 判别，写入 gen.json |
| 模式对了但投错 checkpoint/workflow | 槽位/必填不符，提交失败或参考不生效 | 模式 → §3/§4 的包映射，投前核对 options |
| FL2VA 路径塞 >2 张参考 | 超限截断或提交失败 | 多人多物改 Ref2VA，或拆镜；闸机已卡 |
| prompt 里写空泛 `realistic cinematic / literary style` | 水墨立项出成真人写实片 | 风格锚显式写目标画风＋负向禁 photorealism/live-action/CG/lens。该翻车已登记在 profile `style_evidence`（ink wash＝experimental/1）：[2] 跨模型矩阵据此强制探针＋Style Key＋缓解负向词 |
| 把图声明 weak_reference 且**错述内容**（图里是 A，写成 B） | 模型不参考该图、画面跑偏 | 先开图目视再描述；weak 写清只借什么 |
| 只给头像、不给全身/侧背 | 袍服/身形丢失 | 身份造型同体：一张 4 格定妆 sheet（正脸特写＋全身正/侧/背，一镜绑一格走 Ref2VA） |
| 一张图多标签、按行解析串槽 | wav 被算进图片槽 | 以每行首标签归属文件 |
| results 当 URL 字符串 | 下载报错 | 元素是 dict，取 `['url']` |
| 队列长时间 QUEUED | 误以为参数错 | 先查状态，服务端容量问题非参数问题 |
| Ref2VA 生成类 detailed_description 过短/写成剧情梗概 | 画面与参考脱节、细节丢失 | 官方参考篇幅 350–500 词，硬杠逐 T 点；对白密集以完整对白时间轴为准 |
| gen label 写自由名（tail-frame/style-key 等） | 与正文标签两套命名，对账失效、画面跑偏 | label 只用四种模板标签；角色/样板身份由 role＋ref 承载，闸机正则强卡 |
| Ref2VA 漏段/乱序（只写 3 段等） | 提示词体系残缺、参考不生效 | 段名段序由 profile core_fields 唯一派生，闸机对正文段首全等核对 |

> **待实测悬项**：FL2VA 无音频输入 vs 开口镜绑 tts wav 的口径冲突，
> 以 AutoDL workflow 实际 options 实测后统一修订，此处不臆测口径。

> **画面文字不一棍子放弃。** 官方模板专门规定了写法：招牌、标识、霓虹
> 等**简短可读文字**用英文双引号包住、原文逐字写进镜头描述（如
> `A red neon sign reading "营业中" ...`）；画面文字/UI 清晰度是 H3 的
> 主打强项，值得尝试。**密集汉字、整句字幕**模型仍难稳定，留人工后期，
> 不在词里反复硬扣。
