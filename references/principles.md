# 贯穿全链的原则（Why 与怎么做）

从真实翻车抽出的因果。理解 why，才能在文件没覆盖的情形下做对。

## 1. 单一事实源（Single Source of Truth）
全链仅有的手写事实源是镜头卡（`05-shots/<SHOT>.json`）与资产设计卡
（`06-bom/asset-specs/<ASSET>.json`）；BOM、资产状态、锁定卡、提示词全部
机械派生。
- **为什么**：同一事实写两处迟早不一致；下游会悄悄「补全」上游没写的，补出来的就是脑补。
- **怎么做**：下游只引用已锁定 ID/路径/字段；发现错或缺 → 回镜头卡改、下游重算，不在下游打补丁。

## 2. 画风两层制（Style, two layers）★
| 层 | 内容 | 时机 | 产物 |
|---|---|---|---|
| **风格定向（选路·粗）** | 画种/流派方言、留白哲学、色系家族、参照传统、异象语法 | **编剧之前 [2]** | style-direction.md |
| **风格精冻（执行·精）** | 色值、墨灰档、肤色体积分寸、光比、禁词；样板图 | **BOM 归并后 [9]** | style-bible.md + keys/ |

- **为什么定向要早**：它是视觉之魂，编剧就该朝它写——外化手法受画风支配（淡墨用空停景、半绘半写才用光影）。项目分析所需素材到小说+魂已齐（场景、夜戏、情绪曲线都在正文），不必等剧本。
- **为什么精冻要晚**：具体色值光比须据逐镜机位布光；样板图要等镜头定稿才盖得住实际要拍的镜。
- 定向要**粗而稳**：剧本后续结构变化不应推翻它；若被推翻，说明定向分析没做对。

## 3. 风格定向必须基于「小说简要＋同类作品调研」，不能拍脑袋
- 小说家随稿交 `brief.md`：题材标签、视觉需求统计（具体数字、指回正文）、画风硬约束。
- 出候选**之前**强制完成同类型作品调研（comps：作品/视觉特征/出处 URL 与真实画面）；
  候选描述词从调研中作品的真实长相**自下而上归纳**，不从固定类型表挑。
- 候选必须 N≥3、彼此真正不同、**视觉规格具体可执行**（媒材/线条/色系/留白/光比/异象语法）与关键场景具体处理。换一部片子也成立的候选＝没衬本题，作废。
- 搜索/调研失败必须换词换路拿到图，不许只报片名交差。
- **为什么**：在信息不足时给一个看似精美的方向，是这次「完全错误画风」的根因。

## 3b. 模型边界以 style_evidence 为准，模型随风格组合锁定
- 每个模型 profile 的 `style_evidence` 是画风能力唯一事实源：自由描述词＋四档评级
  （native/supported/experimental/unsupported）＋证据＋缓解，只登记有证据的条目，
  无证据默认 experimental——先探针，不臆测支持度。
- 候选确定后对**全部已登记模型**出矩阵（model-matrix.json）；用户选定「风格×模型」
  组合后才回写 charter 锁定模型。模型不先于风格证据锁定。
- 探针与样板图的结论带日期回写 style_evidence，是更新模型知识的正规时刻。

## 4. 风格＝视觉之魂（冻结后全链围绕）
- 冻结后不可改；编剧/世界/分镜/摄影的产出都受它支配（各环改了什么见 pipeline 对应表）。
- 每道闸含「风格符合」行：禁词、必引样板图、色锚、规格一致可脚本查（写进 `03-style/style-checks.json`）；味道留人审。
连同模型一起冻结：模型随风格组合在 [2] 锁定。
- **改风格定向（含换模型）＝最高级 ECN**：声明波及面，回 [2]、重算矩阵、重批样板图、BOM 与全片资产重算——没有「只改一处」。

## 5. 字段分区（Zones）
| 岗 | 只写 |
|---|---|
| 小说家 | 小说正文、魂草稿、小说简要 |
| 风格 | style 目录（comps/候选/矩阵/定向/经/样板） |
| 编剧 | 剧本 |
| 世界 | geography/axis/brightness |
| 分镜 | 镜卡叙事区＋needs；摄影区留空 |
| 摄影 | 镜卡摄影区；不改剧情 |
| 资产设计 | asset-specs 设计卡；只定外观，不改剧情与镜头 |
| 生产 | 照生产提示词造资产、回状态；不改设计 |
| 写词 | 先判五模式；prompt/gen；段名/段序与首行类型由 profile 派生、gen 不重复手写；不新增情节 |
- 摄影/分镜发现风格承载不了 → 反向打回风格岗，不自己改。

## 6. 画风规格槽位契约 + 样板图首件确认（Style Spec / Style Key）
- **画风规格 Style Spec**：项目画风的唯一结构化事实源（`03-style/style-spec.json`），按 `schemas/style-spec.schema.json` 的**项目无关固定槽位**填写：媒介／形状语言／比例／材质（量化）／Look／色彩脚本／线条／运动／尺度总图／负向。槽内只准写可执行、可核对的具体画面特征，禁空形容词与只写片名；换项目只换槽内取值。脚本按槽提取、按资产类别拼装注入全部生产词；`--gate SS` 强卡槽位齐全、fail-loud。
- **样板图 Style Key**：从**真实项目**里选有代表性的**人物／道具／场景各 2 件**，照设计卡与 style-spec 小批量烧出（共 6 张），用户逐张人审批准。不烧抽象的「色调概念图」，样板就是项目里真实要投产的资产，并承担各类**首件**职责。
- 每件资产提示必须垫样板图；机器可查。
- **为什么**：画风槽位让风格既统一又可泛化；样板与真实资产合一，验证的才是「模型做这个项目真做得稳」，避免样板画一种风格、实际资产另一种长相。

## 6b. 资产设计卡（Asset Design Card）★
每个资产唯一一份详细外观规格（`06-bom/asset-specs/<ASSET>.json`），跨镜复用；镜头卡 needs 只引 ID，不展开外观。
- **为什么**：身高/比例/形制这类信息每资产只该写一次；规格太薄，模型就逐件自由发挥、走样，且写在镜头卡里会随几十镜重复。
- **怎么做**：字段填全（尺度与比例、部件化结构、命名＋hex、材质织理、宫格视图）才准过 G05；简单物与 ≤3 镜、同一视点的简单场景可 single 单图。生产与齐套都照它执行/比对。有错回设计卡改、下游重算。

## 7. 人物定妆 sheet（Character sheet / identity root）
- 主定妆 sheet（sheet_id=main）是角色唯一身份根与首件：一张 1×4 横向均分条
  （左→右＝正脸头肩特写、全身正/侧/背，四格等高，**中性表情**，饰品穿戴
  在身、素底），身份与造型同体；main 批准前，状态变体一律不许投产（depends_on 拦截）。
- 一次生成保证四格是同一人；任一 cell 废整张重烧。**不产静态神情图**——
  表情由视频模型在镜头里现演，静态神情参考反而会串到别的情绪镜。
- 镜头卡对人物只写一行 character_id（必要时标 required_expression）；
  状态变体（易容/受伤/盛装）由 BOM 按 member 展开、变体垫已批 main。

## 8. 锁 / 填 / 投
- 锁：过闸即不可改，要改走 ECN。
- 填：每槽实值或显式 `UNSET` 入待补；禁止留空让下游猜、禁止臆造。
- 投：只投递已锁定 ID/路径/垫图；上游未锁/未审，下游不开工。

## 9. 魂（Soul）常驻
- 魂确认后锁定；镜卡有 soul.motif_marks；母题每次回来意味要变。
- 次数/顺序/方位机器查（soul-checks.json），意味气质留人审。

## 10. 人审权边界
- 文稿失败可打回写手；**图片/音频/尾帧系统只列疑点，通过权在用户**；不自动标 ready/approved。
- 审媒资须让审者看到该件 used_in 与保留方式。

## 11. 尾帧顺序链
- tail_of 与 target_path 在设计时写定（路径可预制）；尾帧内容只能随父镜顺序生成，不可提前预制或用静帧冒充。
- 父尾帧缺失，子镜脚本必须 fail-fast 拒绝提交。

## 12. 编号稳定
镜头/资产编号一经引用不重排；插入用新号，废弃标废弃不回收号码。

## 13. 受控变更（ECN）三档
| 情况 | 处置 | 动上游否 |
|---|---|---|
| 采样偶发 | 重抽 | 不动 |
| 单件回弹 | 强化风格指令＋垫样板图重出，过 G07 | 不动镜卡 |
| 设计/风格要变 | ECN 回源、声明波及面、重过闸、下游重算 | 回 [5] 或 [2] |
- 因果洞/时间线错等悬项进「待决疑点」，停在裁决前不抢跑。

## 14. skill 的边界（终点）
- skill 硬终点＝[14]：每镜拿到 approved 的 mp4 成片素材即交付完毕。
- 组接、BGM、混音、字幕由用户在剪映中完成；skill 不建后期目录、不产出成片。
- 尾帧图与生产提示词都是中间物，不进剪辑。
